# 回退机制

1. 在模型决策边界记录 LLM 请求、返回、工具结果和工作区快照。
2. Rewind 臂暴露 `backtrack_candidates`、`backtrack_commit`。模型可查询候选、选取错误操作之前的检查点，并写下失败经验。
3. 结束旧尝试。还原目标工作区，用记录重放保留前缀的模型和工具结果，到目标点后重新调用模型。历史工具结果用于还原上下文，避免重复执行提交或破坏性操作。
4. 在恢复后的上下文中传入原验收反馈与操作经验。经验应包含已观察到的失败、需撤销的决策、要保留的成果，以及验证新路线的办法。

工作区快照需要覆盖任务交付所依赖的 Git 元数据。网络服务状态、外部操作和运行中进程不在恢复范围。SWE-bench 交付 Git diff，MettleBench 交付完整状态。临时测试和草稿在工作区外。

同失败终点实验克隆工作区、上下文及 `/bench-scratch`，因为草稿目录可能存有原地恢复要用的备份。两臂在首个实时请求前核对状态，并各自重置官方失败计数。共同前缀的启动重放与模型主动执行的实际回退分别记账。

核查效果时，从模型工具请求追到拒绝或恢复事件，再核对分支后的文件和验收进度。区分未查询、查询无提交、提交被拒绝、恢复成功和最后验收通过。Bat 的原始缓存恢复与 Code Image 的早期拒绝分别展示了这几种状态的区别。[实验报告](experiments.md)

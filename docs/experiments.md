# 实验记录

## SWE-bench 探索

早期 Luna6 批次用于调试回退工具、测试入口与官方评测反馈。后来三个可执行的 DS1017 样本中，Continue、Restart、Rewind 分别通过 3、3、2 个，Rewind 臂没有实际回退。这组小样本中，代码修复通常可继续在当前工作区完成。模型、样本和实现版本均有变化，结论限于所测配置。

## MettleBench 三臂

从 78 个有摘要的任务中保守排除 Ripgrep 和 Pandoc 两组运行异常，保留 76 个共同任务。另有四个任务在镜像依赖预检阶段中止。下表汇总一次运行及受影响任务的补测，版本和预算与 AgentRewind 论文不完全相同。

| 策略 | 官方通过 | 未缓存输入加输出 token | 含缓存输入的总 token |
|---|---:|---:|---:|
| Continue | 71/76 | 4,395,201 | 114,025,153 |
| Restart | 73/76 | 4,857,127 | 111,117,351 |
| Rewind | 72/76 | 3,784,712 | 99,947,272 |

较少触发回退的主要背景是大多数任务没有收到官方失败，或原地修复即可继续。另有部分陷入重复失败的运行未查询回退候选。恢复本身也可能修正早期破坏，但任务最后仍因后续交付或资源预算失败。整臂 token 差异包含初始尝试及原地修复的成本。

## 同失败终点对照

选取历史 Continue 未通过的任务，新跑 Continue 以收集自然出现的五次同项失败终点。Ctags 在新跑时通过，未进入配对。该样本用于分析恢复机制，属于有目的的探索性抽样。

Bat 的两臂使用相同的上下文、工作区和 scratch。Continue 新提交五次均在缓存证据项失败。Rewind 主动回到删除原始缓存输入前，恢复原始输入后首次新提交通过。分支后 Rewind 用 331,807 个未缓存输入加输出 token，Continue 用 41,473 个。重复实验在同一终点比较 Restart 与 Rewind，各做两次。

| 任务 | Restart | Rewind |
|---|---:|---:|
| Bat | 2/2 | 2/2 |
| Age | 2/2 | 0/2 |

首批配对筛选中，Ctags 和 Gowsdl 的新 Continue 直接通过，因此未形成失败终点。Age 与 Bat 均形成有效配对。Age 的 Continue 与 Rewind 都未通过。后续扩展队列中的九个 Continue 均通过，没有形成更多配对。

Bat 支持局部回退能挽救特定状态破坏。Age 显示恢复早期状态后仍可能卡在后续交付。Restart 的机制是自动开启新尝试；Rewind 依赖模型识别停止原地修复的时机。观察到的整臂成本还受缓存命中和所选检查点影响。要估计平均收益，需要冻结配置、预定义抽样规则，收集更多自然失败终点并重复运行。
